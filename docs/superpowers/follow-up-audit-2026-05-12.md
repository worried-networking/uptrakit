# Follow-up Audit — Semantic Audit Logs V2 (2026-05-12)

This note records what shipped, what was deferred, and observations that emerged during
implementation but do not change the spec.

## Shipped (Plans A–E)

### Plan A — Proc-macro, typestate, emit APIs

- `uptrakit-audit-log-derive` crate created with `#[derive(AuditView)]` and `audit_actions!`
  proc-macro.
- `AuditActionKind::{Stateful, Event}` enum added; all V1 registered actions classified.
- `AuditEntry<K>` typestate builder replaces V1 flat `AuditEntryBuilder`.
- `AuditEmitter::emit_stateful` and `emit_event` replace `emit_best_effort` (removed).
- `AuditCommitHook` mechanism for deferred journald flush after `tx.commit()`.
- `with_correlation` scoped emitter handle.
- Per-action typed constructors generated by `audit_actions!`.
- `event_test_stub` / `stateful_test_stub` test helpers.
- `serde_json/preserve_order` feature enabled at workspace level.

### Plan B — Producer migration (~100 call sites)

- All state-changing HTTP handlers migrated from `emit_best_effort` to `emit_stateful`.
- All event-class call sites migrated to `emit_event`.
- `AuditView` derived on every entity referenced by a Stateful action.
- `correlation_id` threaded at workflow heads: batch dispatch handler, OIDC initiation,
  scheduler executor entry, service enrollment chain.

### Plan C — Catalog and CI gate

- `crates/shared/audit-log/audit-catalog.toml` seeded with all mutation sites.
- `crates/shared/audit-log/tools/audit-coverage-check/` binary implemented.
- CI gate wired; fails on uncatalogued sites and dead registered actions.

### Plan D — Frontend, CLI, and API surface

- V2 schema migration deployed; V2 tables include `action_kind`, `before_snapshot`,
  `after_snapshot`, `correlation_id`.
- Response DTOs (`AuditLogResponse`, `SystemAuditLogResponse`) extended with V2 fields.
- `?correlation_id` and `?action_kind` filters wired in API and DB query layer.
- CLI `audit-logs list` gains `--correlation-id` and `--action-kind` flags.
- CLI `audit-logs show` renders compact diff for stateful entries.
- Frontend: State tab in detail drawer (before/after key-value diff with highlights).
- Frontend: Correlation ID filter field with copy-button on each row.
- `interactive` flag on `update_history` and `AdminEvent::UpdateStarted` broadcast.

### Plan E — Documentation (this plan)

- `docs/adr/0007-audit-stateful-transactional-emit.md` — new ADR.

- `docs/security/audit-logs.md` — evidence-integrity tiers, storage sizing, V1→V2 cutover.

## Deferred (V3)

Per the spec §"V3 (deferred)":

- Workflow timeline view (grouped by `correlation_id`, cross-table fan-out).
- Per-entity audit history view.
- Analytics dashboards and time-series aggregation.
- Per-action-kind or per-action retention policy.
- Parent/child event linking (event-DAG navigation).
- Compliance-driven legal-hold and immutable archive.
- Agent-side stateful audit emission for agent-authoritative entities.

## Test coverage summary

- `AuditView` derive: determinism test auto-generated per entity; secret-leak regression tested
  for every entity embedding `EncryptedString`, `MaskedUrl`, `MaskedEmail`.
- Typestate builder: compile-fail tests via `trybuild` for all misuse classes.
- Producer integration tests: one per representative Stateful action; assert exactly one audit
  row written; before/after snapshots match observed entity state; forced rollback drops row.
- `audit-coverage-check` tool: unit-tested against synthetic workspace fixtures.

## Known caveats

- `#[audit(truncatable)]` field attribute is wired but not yet applied to any entity field in
  V2. The preferred path for known-large fields is `#[audit(project_with = "<fn>")]` with a
  summary projector. `truncatable` remains available as a last resort.
- The `audit_log.filter` per-tenant enforcement setting is retained in config/state but
  centralized producer-side enforcement is deferred; the coverage gate is the substitute.
- Cross-table correlation queries (events spanning `audit_logs` and `system_audit_logs`) require
  API-layer fan-out; the current `?correlation_id` filter is per-table only. V3 will address
  this when the workflow timeline view is designed.
- V1 audit rows are dropped by the V2 migration with no transformation. Compliance-posture
  deployments should consult `docs/security/audit-logs.md` for the optional pre-migration export.
